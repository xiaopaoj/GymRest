# 0.5.0 模板、动作库、顺序建议与负重记录

## 已确认范围

用户确认三分化推/拉/腿与五分化胸/背/腿/肩/手臂，接受逐组重量及可选次数；先建立动作数据，评估免费素材，素材缺口可由后续人工补充。随后追加要求界面同步优化。此授权替代早期不开发重量/次数的范围，但不扩展为身体分析或自动加重处方，也不授权本轮推送。

## 使用流程与界面

- 计划：首页新增模板入口。三分化3个训练日、五分化5个训练日，选择每周目标1–7次、可用器材与重点部位；每个动作位置可换成同模式/主要部位相近的动作。预览实际动作顺序和总组数后创建为一套新计划，不覆盖已有计划。模板采用3组、复合动作10次/120秒组间、孤立动作12次/60秒组间、120秒动作间作为可编辑起点，不预设重量，不承诺最优。每周目标只是安排参考，不是固定星期的日历。
- 动作：新增独立动作库页，51个常用动作，中文/英文搜索，主要肌群和器材筛选；动作详情包含主要/辅助肌群、要点、器材、组间/动作间休息、参考次数、来源与许可，以及替代项。肩细分前束/中束/后束。肌群细分属于编辑整理，代表常见侧重，不能当作完全孤立或精确刺激比例。
- 编辑：训练日可从动作库添加并附带最多4个替代项，也保留手动动作；主动作/替代项独立设置预设重量和次数。新建模板及复制均重建位置UUID，catalogID保持稳定。
- 训练：将本组重量/次数显示为独立卡片，可在做组前或组间为下一组修改；完成本组时记录。休息控件及完成按钮继续显著显示，已完成组可折叠查看。锁屏显示本组设置，沿用它完成本组；改值只在App内进行，不把锁屏点按当作新输入的重量。
- 记录：逐组展示实际动作、重量口径/单位、次数及器械备注；修改后续组/源计划不改写既有记录。旧记录仍显示已有计数与名称，重量/次数为未记录，不推算补填。

### 人工补充方法

1. 按稳定catalogID在目录定位条目；从候选清单选择或另找免费、允许此用途的素材，核对实际动作、作者、许可与修改要求。优先同一人物/绘制方式、背景、画幅和肌群高亮风格，器材图也采用同一套表现。
2. 将完整循环短视频（mp4/mov）及器材图片（png/jpg/jpeg/webp）放入 `GymRest/Resources/CatalogMedia/`，文件名全局唯一；确认Xcode资源复制。
3. 修改该条目的media：status设为approved，填写animationAsset/equipmentAsset的文件名、author、sourceURL、licenseURL。许可和作者不得为空，不使用远程裸链作为运行时依赖。至少提供一项资源，可分别补齐演示和器材图。
4. 运行 `python3 -m unittest discover -s scripts -p 'test_*.py'`。数据检查核验引用与文件存在性；人工仍须核验动作正确、素材授权、循环完整和统一风格，再通过Xcode验证播放。新增资源的许可要求及修改说明应随版本保留。

播放实现使用Apple AVQueuePlayer/AVPlayerLooper与VideoPlayer，静音循环，离开页面停止，不增加音频后台保活。参见[AVPlayerLooper](https://developer.apple.com/documentation/avfoundation/avplayerlooper)和[VideoPlayer](https://developer.apple.com/documentation/avkit/videoplayer)。实际素材缺口不影响原计时/训练记录。

## 顺序建议

均衡时优先多关节动作；选择重点部位时，主要肌群命中该重点的动作优先，其余按多关节/单关节与原顺序稳定排序。自定义未关联动作固定在原位置，不凭名字猜肌群。建议同时显示理由、原顺序和新顺序，只有用户主动采用才生效。

训练中只调整当前及后续尚未开始的动作；已有完成组的动作位置固定，休息时不提供重排。提交前核对interactionID、阶段及全部候选ID，同步调整动作/原始快照/名称/逐组数据/本组草稿数组，防止重量或记录串位。旧预览无法覆盖新进度。

依据为[ACSM 2026立场文件](https://doi.org/10.1249/MSS.0000000000003897)：优先练习与力量适应有关，不能据此承诺某一中束/后束顺序必然增肌更多。UI明确其为可调整的编排建议，不做自动医疗/康复处方。

## 重量、次数与数据兼容

- SetValues区分total总重、perHand单只、machine器械标重、bodyweight自重、added额外负重、assistance辅助；单位kg/lb/level档位。0重量与未填nil不同，次数可留空或为1–1000，重量为有限0–10000；自重不填重量，档位仅用于器械。单位/口径改变时编辑器清空重量，避免悄悄把kg改标为lb。
- ExerciseSpec/Alternative的prescription是计划值；TrainingSession.setDrafts是当前/下一组草稿，performances是逐组已完成快照。完成操作才追加一次实际记录，提醒注册失败不重复计组；提醒重试不追加第二条测量。
- 新训练只从最近50条历史中找相同动作catalogID（自定义用准确名称）、负重口径、单位和器械备注的记录，填补未设置的计划字段。显式预设优先；不同器材备注、kg/lb、总重/单只不混用，也不做不可靠的器械负荷换算。这个回看上限不删除历史。
- 替代项切换不继承不相关的负重；可取该替代项本次已完成组或匹配历史。每组保留当时实际动作与数据，不改写过去组。
- 旧快照/JSON缺少新字段时仍可解码；旧完成组若需要接入新记录数组，其values/profileKey为空，不编造重量与次数。新可选SwiftData字段performancesData与weeklySessions保持默认存储位置；真实跨版本覆盖安装仍需设备验收。
- 导出有catalogID、prescription或weeklySessions时使用version3，仍接收version1/2。version3不把演示文件或训练历史塞进计划JSON。已有覆盖导入继续保留训练历史/健康关联/当前快照，目标预览也包含每周目标，防止确认后修改被忽略。
