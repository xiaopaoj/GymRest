# 训练计划 JSON 格式

> 0.7.0工作区：计划内容格式不变，导入增加字段错误定位和动作关联预览，支持普通文本文件标识及单个JSON代码块。完整备份另有独立入口和格式，不能当计划导入。见[优化说明](OPTIMIZATION_0_7_0.md)。

设置 → 计划 JSON 导入与导出。支持选择JSON文件或直接粘贴完整文本。导出为 UTF-8 JSON，版本 `1`。计划及动作的数组顺序决定排序，不导出训练记录或健康数据。

```json
{
  "version": 1,
  "plans": [
    {
      "id": "E4E5F4F7-A9F1-4DA4-814D-D1719DF8408D",
      "name": "胸部训练",
      "exercises": [
        {
          "id": "4D6BDD2C-0A24-4107-84BE-AB3B5F70B01F",
          "name": "卧推",
          "sets": 4,
          "restSeconds": 90,
          "restAfterLastSet": false,
          "restOverrides": {"3": 120}
        }
      ]
    }
  ]
}
```

计划、动作名称去除空白后不能为空，最长100字符；组数1–100，默认和覆盖休息秒数1–86400，覆盖组号须在1至组数范围内。ID须为有效UUID，同一文件计划ID不重复，同一计划动作ID不重复。休息覆盖字段可省略，兼容旧版动作数据。末组覆盖不会隐式启用末组休息。

单次导入最多10MB，不设置计划或每计划动作数量上限。文件先整体解码和校验，再预览并确认所选导入方式。默认追加，生成新ID并保留已有内容；也可明确选择覆盖所选计划或全部计划。保存失败整体回滚。重复追加会产生副本，不做隐式合并。

## 替代动作

完整可导入示例：[chest-with-alternatives.json](../examples/chest-with-alternatives.json)。打开文件复制全部文本，在App设置的“粘贴JSON文本”中粘贴，然后“校验并追加导入”；也可下载保存为`.json`后选择文件导入。

每个动作可增加可选的 `alternatives` 数组，每项包含 `id`、`name`、`restSeconds` 和可省略的 `restOverrides`。替代项共用所在位置的 `sets` 和 `restAfterLastSet`，不另加动作位置/总组数，默认休息和按组覆盖分别独立。该位置的主动作及替代项ID不能重复，非法替代项会使整个文件拒绝导入。

训练的待训练状态可切换到替代项或原动作；休息/暂停时须先结束或跳过休息。完成组数不清零，历史逐组保留实际使用的动作名称；训练中的选择不修改源计划。新计划导入、复制会为主动作和替代项生成新ID。旧JSON无alternatives时按无替代项处理。

## version 2：计划 → 训练日 → 动作

version1的plans继续按训练日解读。version2增加顶层programs（id/name），每个plans条目可用programID归属上层计划。所有引用须有效，导入后上层/训练日/动作/替代项ID重新映射。通用导入保留新版分组；从具体计划详情导入则明确归入该计划。

用户五分化文件的分组版本：[five-day-split.json](../examples/five-day-split.json)，保持原5个训练日、26动作和88组及替代配置。已导入的旧训练应通过“整理已有训练”归组，避免重新导入产生副本。


## 动作间休息（可选字段）

每个主动作可添加 `transitionRestSeconds`，整数范围0–86400秒。完成该动作最后一组且后面还有动作时，先按此字段休息，再进入下一动作；0明确表示直接切换。它独立于 `restSeconds` 与 `restOverrides`，不会叠加两段休息。

例如卧推组间90秒、完成全部组后换划船前休息180秒：`"restSeconds": 90, "transitionRestSeconds": 180`。最后一个动作不执行动作间休息；若显式启用 `restAfterLastSet`，仍可在训练结束前使用末组覆盖或组间秒数额外休息。

旧JSON省略或为null时保留原语义：末组由restAfterLastSet决定，秒数取末组覆盖或组间秒数。无需重新导入、不会自动修改旧计划。编辑动作时把旧行为展开为明确的动作间秒数；通过App新建动作时，初始动作间秒数取当前默认休息值，可改为0。

替代项共用所属主动作的动作间休息，不另设该字段。复制、导入导出、活动训练快照与历史动作数据保留新配置；正在训练时编辑计划只影响之后新开的训练。

完整示例：[transition-rest.json](../examples/transition-rest.json)。version1和version2均支持此可选字段，旧版App可能忽略它，配置此字段的计划请在新版使用。


## 追加与覆盖导入

文件导入和粘贴JSON使用同一套流程：选择方式及目标 → 校验 → 查看导入内容与影响范围 → 明确确认后保存。

- **追加导入（默认）**：保留所有本地计划，生成副本。分组和归属规则同上。
- **覆盖所选计划**：选择一套已存在的本地上层计划，保留它的ID和名称，移除其中全部旧训练日，再将文件内全部训练日归入它；文件自带分组在此模式下合并到目标。其他计划、未归类训练日不变。不按同名或文件ID猜测匹配。
- **覆盖全部计划**：移除全部本地上层计划与训练日（包含未归类），再按文件重建。新版保留文件分组，旧版归入确认页显示的新计划名称。

覆盖不是逐条合并：目标范围内未出现在文件中的旧训练日也会移除。训练日、动作与替代项采用新ID；历史快照、健康关联、当前训练进度、偏好不在覆盖范围内。当前训练继续使用开始时的快照，覆盖后的配置用于之后新开的训练。

确认页显示方式、目标、导入名称与数量，以及将被替换的本地计划和训练日。确认数据包含输入文件及本地目标内容；确认期间如目标被修改/删除/重排、归属改变，或存在未保存编辑，停止覆盖并要求重新预览。其他计划已保存的修改不阻塞覆盖所选计划。空文件不支持覆盖；非法文件先拒绝，删除与导入只进行一次保存，失败回滚原有内容。

需要保留原计划时可先导出计划JSON；现有导出仍不包含训练历史。


## version 3：动作目录、预设负重与每周目标

version3沿用version2分组结构，兼容读取version1/2。上层programs条目可含weeklySessions（1–7，目标次数并非固定星期）。主动作与替代项可含catalogID和prescription；目录标识不在复制/导入时重建，位置UUID仍重新生成。

prescription为可选对象，字段weight（可空有限0–10000）、repetitions（可空或1–1000）、unit（kg/lb/level）、kind（total/perHand/machine/bodyweight/added/assistance）、equipmentNote（至多80字）。bodyweight不填weight，level仅配machine。例：`"prescription":{"weight":20,"repetitions":10,"unit":"kg","kind":"perHand","equipmentNote":"健身房A哑铃"}`。该值是计划预设，训练可逐组调整；实际完成记录保存在训练历史，不在计划JSON中。

有这些字段时导出标为version3，使不支持的新旧客户端边界明确。没有新字段仍可导出version1/2。缺少新字段的旧记录显示未记录，不回填猜测值。媒体资源不嵌入此JSON，目录素材与许可另见docs/TEMPLATES_AND_LOADS.md。
