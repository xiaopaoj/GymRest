## 素材包方案

### 产品与打包

推荐把动作目录/名称/文字步骤留在IPA，PNG与可变的配图映射移入独立版本的素材包。训练计划、训练历史与素材分别存储，不需要修改现有计划JSON v3。

提供两个构建选项：

| 构建项 | 行为 |
|---|---|
| `MEDIA_MODE=external`（日常默认） | IPA不带动作PNG；发布同版本或兼容版本的独立 `.gymrestmedia` 文件，用户首次导入后离线使用 |
| `MEDIA_MODE=bundled` | IPA带同一份官方素材包作初始化资源，首次启动复制/安装到同一素材管理器，适合首次安装或离线分发 |
| `MEDIA_SEED_POLICY=preserve`（默认） | 已有可用的本地官方包时保留，不因安装新IPA重复导入或覆盖 |
| `MEDIA_SEED_POLICY=updateOfficial` | 首次启动遇到更高revision且兼容的随包官方包时，只更新该官方包；保留旧包供回滚，不改动用户包 |

无随包素材时，覆盖策略没有可执行内容：轻量IPA不能凭空恢复未导入的图片。官方包降级须在素材管理页主动选择；不因App版本较新而强制覆盖更高素材版本。暂不提供静默清空全部素材的编译开关。

普通覆盖安装且保留同一Bundle ID和App数据容器时，Application Support中的素材可继续使用；卸载、清除数据、换Bundle ID或某些侧载工具重装方式可能丢失，不能承诺重新安装后一律保留。现有版本素材在只读Bundle内：升级到轻量IPA不能读取已被替换的旧Bundle，首次切换要导入独立包，或先安装带包的过渡版本。

### 存储、格式与匹配

- 保存到`Application Support/MediaPacks/<packID>/<revision>/`，不放到可被系统自动清理的Caches；只持久化相对路径，不保存沙盒绝对路径。外部来源包不自动备份到iCloud；单独提供导出/恢复入口。
- `.gymrestmedia`采用ZIP容器，包含manifest、图片、许可与逐帧来源。iOS没有可直接假定存在的通用Foundation ZIP解包API；实现阶段采用固定版本、经许可核对的ZIP库，并在提取前逐条验证路径/条目类型/大小，禁止直接无校验整包解压。
- manifest包含`format`、`schemaVersion`、`packID`、单调递增`revision`、`minAppVersion`、目录兼容标识、每张图片相对路径/字节数/SHA256、动作映射与明确展示帧、浅色背景标记、来源作者/许可/审核备注。
- 官方包以稳定catalogID匹配，动作改名不丢配图；第三方包无ID时才用唯一规范化名称/别名辅助匹配，重名/冲突必须预览手选。未知动作列为未匹配，素材导入不暗中创建或改写训练动作。
- 配图解析层使用“用户明确选择的兼容覆盖包 → 官方安装包 → 随包后备资源”。本地素材包提供新映射后，按媒体版本刷新视图及UIImage缓存，不能继续只用动作ID作为task标识。
- 官方运行包只包含当前获准展示的775张，不携带已暂停展示帧；另行发布完整912张原始素材与审核清单供追溯，保留全部原文件、许可及哈希。更新后的审核清单可撤回不准确帧，旧Bundle后备资源不得绕过撤回规则。

### 导入、更新与UI

设置增加“动作素材”页：当前官方包版本、覆盖动作数、容量、未匹配数；导入、导出、检查更新、回滚和移除。导入前预览新增/更新/缺失/冲突和预计占用，默认只安装新包或替换同packID版本；替换整库或覆盖用户选择不作为默认行为。

流程：文件复制到临时区 → 校验manifest兼容性与资源上限 → 验证路径/哈希/图片可解码/许可完整 → 生成预览 → 安装新版本目录 → 原子切换活动索引。失败、取消、空间不足或App中断都保留旧索引和旧包；下次启动清理未激活临时目录。相同packID/revision但内容哈希不同应拒绝，避免同版本悄悄变更。

初版限制：压缩文件≤100MiB、解包总量≤200MiB、文件≤3000、单图≤10MiB且≤4096×4096，限制压缩比并检查实际读取量；拒绝符号链接、绝对/上级路径、重复路径、加密条目和非许可格式。SHA256用于完整性校验，不冒充来源认证；官方更新只从固定HTTPS发布来源获取，自动更新前应增加可信签名验证，首版不后台静默下载执行。

训练进行中可以查看素材，但把导入/切换/删除推迟到训练结束，避免当前示意突然变化。缺包时显示“尚未安装素材包”与入口；已装包但无准确配图时显示“暂无准确配图”，避免把不同问题混为一谈。器材图片仍不展示。

初版手动下载/文件导入即可，无服务端账号；以后可加用户主动“检查更新/下载”。同一官方包可跨多个App版本复用。完整训练备份继续不内嵌大图，可增加可选素材包版本引用，但还原后须校验实际包是否存在。

## Watch开训提醒能力与方案

核对Apple官方文档后：公开的会话镜像API用于自有watchOS App与对应iPhone App。当前iPhone-only GymRest没有公开且可靠的通用接口，查询Apple系统“体能训练”或任意第三方Watch App是否正在记录。HealthKit中没有查到已保存运动、Watch是否连接、心率变化、活动圆环变化，都不能当作“没开训练”的依据。不能用启动一个测试会话来探测，避免干扰用户的现有运动。

### 近期建议：开训前手动提醒

不增加健康权限即可在开始一场新训练前提供可选提醒，设置项“开始训练前提醒开启Watch训练”，默认关闭；需要Watch记录的用户主动开启。文案：“如需Apple Watch记录，请在手表上开启「传统力量训练」等合适类型。GymRest目前无法自动确认手表是否正在记录。”

按钮：“已在手表开启，开始训练”“本次不记录，继续”“取消”。确认只是用户自述，不显示为“已检测”。只对新训练提醒一次；继续训练、重启恢复、每一组操作和通知回到App均不重复弹出。用户取消时不创建训练记录、不开始提醒或计时；真正开始GymRest训练后才记开始时间。当前计组/休息和锁屏提醒不受手表状态阻塞。

此提醒是防遗漏方案，无法满足自动检测，尚未添加到App。本页先规划，不将手动确认冒充自动检测。

### 后续可实现：GymRest Watch App联动

若希望自动确认/一键联动，需要新增真正的watchOS伴侣App与HealthKit训练记录写入能力：iPhone发起启动请求，Watch取得授权并建立自己的HKWorkoutSession，向iPhone镜像。只有收到对应会话running状态才显示“GymRest Watch训练进行中”；请求成功仅表示Watch App被唤起，不代表已开始运动。paused、ended、未连接/过期状态明确区分，失联不推断已结束。

该方案确认的是GymRest自己的Watch训练，不能宣称检测到系统“体能训练”。已在系统App记录时，继续使用系统App并手动确认，避免重复启动/结束别人的会话。开发时需明确单一健康记录写入方、完成/取消行为与重复保存去重，新增watchOS目标、签名、授权及实际iPhone/Watch配对安装测试；不能沿用当前只读权限视为已满足。Linux无Apple SDK，API实际签名和打包能力要在Xcode验证。

官方来源（2026-11-26核对）：
- [workoutSessionMirroringStartHandler](https://developer.apple.com/documentation/healthkit/hkhealthstore/workoutsessionmirroringstarthandler)：接收镜像会话，连接恢复时可能多次回调。
- [startMirroringToCompanionDevice](https://developer.apple.com/documentation/healthkit/hkworkoutsession/startmirroringtocompaniondevice(completion:))：从自己的watchOS App向伴侣iPhone发起镜像。
- [startWatchApp](https://developer.apple.com/documentation/healthkit/hkhealthstore/startwatchapp(with:completion:))：唤醒伴侣Watch App，完成回调不等于session running。
